Ask for a feature in plain words. Get back a reviewed, tested change.

intentable turns a GitHub issue into a pull request. The people who know what the site needs write the issue and answer questions in comments, so they never open a terminal. An agent does the writing, design and code, every change gets its own preview of the site to try before it's merged, and checkpoints, some automatic and some human, stop anything unchecked from reaching the site.

Who does what

People decide. The agent does the rest.

Everything happens on the GitHub issue, in comments. Each person steps in only where their judgment matters.

The person who asks

Knows what the site needs; doesn't need to know how it's built.

  • Opens an issue in plain words
  • Answers the agent's questions
  • Gives feedback on sketches and picks one
  • Tries the change on its preview

The owner

Holds the two gates that matter most.

  • Approves the proposal before anything is built
  • Checks the preview, then reviews and merges the code

The agent

Does the writing, design and code.

  • Triages, and asks what's unclear
  • Writes the proposal, with reviews and sketches
  • Builds it, tested, up to the pull request
  • Puts up a preview and links the pages to check

How it works

Eight steps, the same for every request

The issue's label shows everyone where it stands, and it's always assigned to whoever holds it: the person who asked while a question waits on them, the owner otherwise.

  1. AskSomeone on the intake list opens an issue.
  2. ClarifyThe agent asks one question at a time until it's clear.
  3. ProposeA written proposal, checked by three independent reviewers, with sketches when there are screens.
  4. ShapeFeedback starts a revision; a sketch's letter picks it.
  5. ApproveThe owner comments /approve.
  6. BuildBuilt in a fresh sandbox, tests green at every step, then a final check.
  7. PreviewEach pull request gets its own copy of the site, on last night's data. The link lands on the issue.
  8. ShipThe owner checks the preview and merges. The issue closes once the change is live.

What it guarantees

Consistency, reliability and quality, built into the steps

Non-technical people can drive the work because the guarantees don't depend on them, or on the agent, getting everything right.

Consistency

Every change starts from the truth.

  • Every request follows the same steps, in the same order.
  • Each change is written against the site's living specification and design rules.
  • When a change ships, the specification is updated for the next one.

Reliability

Nothing half-done gets through.

  • Each run starts in a fresh, isolated sandbox.
  • Nothing is committed unless the whole test suite passes.
  • A final check refuses any build that breaks a rule, and missed notifications are caught up within minutes.

Quality

More than one pair of eyes, every time.

  • Three independent reviewers check every proposal.
  • The person who asked picks the design before any code is written.
  • The owner approves both the plan and the finished code.
  • Every change can be tried on a preview, with real listings, before it's merged.

Under the hood

Ordinary tools, wired together

intentable is our own tooling, not a product. It runs today on StageHopper, a calendar of live music across New England.

GitHub issues
Where people ask, answer, pick and approve. Labels and assignees show where each request stands.
The bridge
A small service that hears GitHub's notifications, starts the agent's runs and relays their questions back.
OpenSpec
Proposals, testable requirements and task lists, kept beside the code as the site's living specification.
Fabro
Runs each workflow (triage, clarify, propose, build) as a graph of steps, and keeps a record of every run.
Daytona sandboxes
A fresh, isolated machine for every run, so one run can't leave a mess for the next.
Preview environments
Each pull request runs on Cloud Run, on its own Neon branch of a nightly copy of the live data with people's details removed. It sends no email, and it's gone once the change merges.
Claude Code
The agent inside each step, doing the reading, writing, design and code.
